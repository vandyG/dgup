# Lessons Learned
- Real world data is messy and the patterns are not always clear.
- Even though there were identifiable patterns they were very volatile at the atomic level but the bird view showed the patterns clearly.
- Even though the problem statement was simple, the requirements were simple the implementation invlolved a lot of customizations and conplexity to accomodate real world use case. For ex: The gas usage for the current day is not available midway until the next day hence an expanding window rolling forecast was used in this project that used the data upto t-2 days to forecast the t th day.
- With every discussion there were new additions to the problem statement and it kept evolving so we had to keep accomodating new requirements.
- To communicate to the stakeholders we had to prepare and balance between technical details and KPIs and results so as to adapt it for the stakeholders.
- Theory doesn't always translate to real world success. For ex: A simple Gradient boosting model perfored the best instead of the latest and greatest.
